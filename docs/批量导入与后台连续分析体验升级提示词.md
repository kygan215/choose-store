# 批量导入与后台连续分析体验升级提示词

请在现有“门店周边 POI 搜索与分析平台”上继续做增量升级，保留已经完成的批量门店 POI 详情、单店报告、任务总报告和多店对比，不重写项目架构。

## 一、上传与文件反馈

1. 上传 Excel、CSV 后必须出现明确的成功反馈，显示文件名、文件大小、有效门店数、错误行数和重复行数。
2. 上传解析失败时必须显示可理解的错误原因，并保留“删除文件/重新选择”入口，不能让用户停留在无反馈状态。
3. 当前版本可以一次处理一个文件，但必须把文件作为可删除、可替换的独立上传项展示；后续应能自然扩展为多文件队列。
4. 删除文件后，同时清空该文件的预览、字段映射、门店勾选和创建任务状态。

## 二、门店筛选与选择

1. 文件解析成功后，所有有效门店默认全选。
2. 数据预览增加复选框列，并显示“已选 X / 可用 Y 家”。
3. 支持按门店名称、品牌、城市、区县、地址或门店编号搜索筛选。
4. 支持全选当前筛选结果、取消当前筛选结果和恢复全选。
5. 创建批量任务时只提交用户勾选的门店；未选择任何门店时禁止创建并给出提示。

## 三、后台连续匹配

1. 用户点击一次“开始匹配”后，系统应在后台连续处理该任务的全部门店，不再要求反复点击“开始/继续匹配”。
2. 匹配过程中持续同步已处理数量、总数量、百分比、当前门店、成功数量和失败数量。
3. 匹配开始后提供“暂停任务”和“结束任务”按钮。暂停后可继续；结束后保留已完成结果，不再自动继续。
4. 批量模式自动采用评分最高的有效候选，不再要求用户逐家确认低置信度门店。
5. 只有高德完全没有返回有效候选或接口发生不可恢复错误时，才将门店列为失败；页面必须展示失败门店名称和原因。

## 四、后台连续完整分析

1. 匹配完成后，用户只需点击一次“运行完整分析”，系统即在后台连续完成所有已匹配门店的 POI 查询、商圈画像和潜在人群画像。
2. 长时间分析不能占用一个持续等待的前端请求；刷新页面或切换页面后仍能恢复任务进度。
3. 分析过程中持续显示进度条、当前阶段、当前门店、成功数量、失败数量和预计剩余门店数。
4. 分析过程同样支持暂停、继续和结束。
5. 分析全部完成后，页面自动提示用户可以进入“门店详情与对比”，无需再次操作。
6. 允许安全的有限并发，默认同时分析 3 家门店；并发数应可配置，避免超过高德接口限制。

## 五、任务页面布局

1. 在“分析任务”页面顶部优先展示当前任务监控卡片，历史任务列表下移并适当压缩高度。
2. 当前任务卡片至少展示：文件名、任务阶段、进度百分比、已处理/总数、成功、失败、当前门店和最近更新时间。
3. 当前任务运行中显示暂停和结束按钮；暂停时显示继续按钮；匹配完成时显示“一键运行完整分析”；全部完成时显示“门店详情与对比”和导出入口。
4. 页面每 2 秒刷新任务状态，长时间过程必须保持可见进度，不使用无反馈的按钮等待状态。
5. 失败门店在当前任务卡片内单独展示，不再弹出候选确认面板。

## 六、容量与对比

1. 单个批量任务继续支持最多 5,000 行导入，后台自动连续处理全部已选门店。
2. 任务结果列表支持展示全部已分析门店，不因固定批次大小要求用户继续点击。
3. 重点门店横向对比上限由 4 家提升至 12 家，并显示当前已选数量。
4. 当门店较多时，结果表支持搜索、筛选和滚动，不牺牲逐店详情与导出能力。

## 七、状态与可靠性

1. 后台任务状态和控制指令写入数据库任务配置，刷新页面后仍能看到当前状态。
2. 同一个任务不得重复启动两个后台执行器；重复点击开始时返回当前运行状态。
3. 重复运行完整分析不得产生重复画像或重复 POI。
4. 保留原有接口作为兼容入口，但新版页面默认使用后台连续任务接口。
5. 所有错误使用中文描述，并保留 `request_id` 便于排查。

## 八、验收标准

1. 用至少 10 家门店的文件验证上传成功反馈、删除文件、搜索筛选、默认全选和部分选择创建任务。
2. 点击一次开始匹配即可自动处理全部所选门店，并能暂停、继续和结束。
3. 点击一次运行完整分析即可处理全部已匹配门店，期间持续显示进度，结束后直接进入详情与对比。
4. 没有候选的门店能明确显示名称和失败原因，不出现逐店人工确认步骤。
5. 重点对比可选择最多 12 家门店。
6. 后端自动化测试、前端构建和代码检查全部通过，并在本地页面完成交互验收。
