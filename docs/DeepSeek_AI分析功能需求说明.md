# DeepSeek AI 分析功能需求说明

## 1. 文档目的

在现有“门店周边 POI 搜索与分析平台”中增加 DeepSeek AI 解读能力，将 POI 圈层统计转化为较易理解的人群画像分析。

本阶段仅形成需求说明，不实施代码接入。

## 2. 功能定位

AI 仅用于解读已有 POI 统计结果，不负责调用高德地图，不修改高德返回的数据，也不判断门店是否适合开店。

AI 分析范围：

- 周边主要潜在人群类型；
- 主要年龄段及其估算占比；
- 人群消费能力倾向；
- 不同搜索半径圈层之间的人群差异；
- 支撑结论的 POI 统计依据；
- 分析可信度与数据局限。

明确不包含：

- 是否适合开店的判断；
- 开店评分或投资建议；
- 零食商品、陈列或促销建议；
- 将推测结果描述为真实人口、收入或消费统计。

## 3. 已确认的产品需求

### 3.1 触发方式

- POI 分析完成后不自动调用 DeepSeek。
- 用户主动点击“生成 AI 分析”按钮后才发起请求。
- 重新生成前应提示将产生新的 API 调用和分析版本。

### 3.2 单门店 AI 分析

- 生成约 300 字的简短分析。
- 使用专业研究报告风格。
- 年龄段由 AI 根据每家门店的设施结构动态划分，不使用固定年龄区间。
- 允许输出年龄段估算百分比，但必须显著标注为 POI 代理推测值。
- 每条主要结论应包含判断依据和可信度。
- 使用用户已经选择的全部搜索半径，分析不同圈层之间的变化。

### 3.3 多门店 AI 对比

- 支持对批量任务中的门店生成 AI 对比分析。
- 一次最多选择 10 家门店。
- 对比内容包括共同特征、主要差异、各门店人群结构差异和消费能力倾向差异。
- 不输出门店优劣排名和是否适合开店的结论。

### 3.4 展示与导出

AI 结果需要展示在：

- 单门店详情页；
- 批量门店对比页；
- 单门店导出报告；
- 多门店对比导出报告。

### 3.5 历史版本

- 重新生成时不覆盖旧结果。
- 保存每一次 AI 分析版本。
- 每个版本至少记录：生成时间、模型、提示词版本、输入统计摘要、输出结果、可信度、调用状态和 Token 用量。

## 4. 发送给 DeepSeek 的数据范围

只允许发送汇总后的 POI 统计数据：

- POI 分类；
- 各分类数量；
- 各搜索半径内的数量；
- 各圈层密度或占比变化；
- 统计样本总量。

不得发送：

- POI 名称；
- POI 详细地址；
- 完整门店地址；
- 高德 POI ID；
- 用户上传文件原文；
- 会员、订单或其他个人信息。

可发送非敏感的门店标识，例如“门店 A”或系统内部匿名编号，用于多门店对比。

## 5. 模型及接口要求

- 默认模型：`deepseek-v4-flash`。
- API Base URL：`https://api.deepseek.com`。
- API Key 只能保存在后端环境变量 `DEEPSEEK_API_KEY` 中。
- API Key 不得出现在前端代码、浏览器请求、日志、导出报告或 Git 仓库中。
- 使用 JSON 结构化输出。
- 服务端必须校验 AI 返回的数据结构，不能直接信任模型输出。
- 空内容、JSON 解析失败、超时、429、500、503 等情况最多自动重试 2 次。
- 重试仍失败时保留已有 POI 分析结果，并向用户显示可理解的失败原因。

      "estimated_share": "估算比例",
      "characteristics": "人群特征",
      "evidence": ["POI 汇总统计依据"],
      "confidence": "高/中/低"

## 7. 页面交互要求

### 7.1 单门店

- POI 分析完成后显示“生成 AI 分析”按钮。
- 点击后展示明确状态：整理 POI 统计、AI 分析中、保存结果、生成完成。
- 完成后自动滚动或切换到 AI 分析结果区域。
- 页面显示生成时间、模型名称、可信度和“重新生成”入口。
- 可查看历史版本。

### 7.2 多门店

- 用户先选择 2 至 10 家门店。
- 点击“生成 AI 对比分析”后发起一次对比请求。
- 生成期间不阻塞原有门店详情、POI 明细和普通对比功能。
- 对比结果可保存、查看历史版本并导出。

## 8. 可信度与免责声明

页面和导出报告必须明确显示：

> 本结果根据周边 POI 分类、数量和圈层分布进行代理推测，不等同于真实人口普查、客流、收入、消费能力或销售数据。年龄占比为估算值，仅供门店周边环境理解使用。

可信度建议综合以下因素计算：

- POI 样本总量；
- 有效分类覆盖数量；
- 不同圈层数据是否一致；
- 是否存在样本过少或类别明显缺失；
- AI 结论是否有足够的统计依据。

## 9. 部署要求

- 代码按未来 Linux 云服务器部署标准开发。
- 第一阶段在本机环境测试。
- 本机和服务器使用相同的环境变量名称和数据结构。
- AI 请求只能由后端发起。
- 后续迁移服务器时无需修改前端调用逻辑。

## 10. 验收标准

1. 没有 API Key 时，页面明确提示未配置，其他 POI 功能不受影响。
2. 用户不点击按钮时，不产生 DeepSeek 调用费用。
3. 单店能够生成约 300 字的专业人群分析。
4. 年龄段由 AI 动态划分，并允许显示标注为估算的百分比。
5. AI 输入中不包含 POI 名称和详细地址。
6. 每条主要结论具有统计依据和可信度。
7. 支持 2 至 10 家门店生成 AI 对比。
8. 不产生开店适合度、投资或商品销售建议。
9. AI 结果可写入单店报告和对比报告。
10. 重新生成后旧版本仍可查看。
11. DeepSeek 调用失败不会破坏已有 POI 数据和分析任务。
12. API Key 不出现在浏览器、Git、日志和导出文件中。
