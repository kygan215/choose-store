# 品牌查询任务排查

在「品牌门店库 → 查询任务」找到任务编号，点击「日志与监控」。面板每 5 秒刷新，可暂停刷新、筛选警告和错误、下载诊断 JSON。日志不包含密钥、密码或活动销售额，保留 30 天。任务及诊断接口沿用组织和任务所有者权限。

进度表示已完成的「城市 × 品牌」组合；同一城市内的分页搜索和逐条入库不会使这个数字增加。应同时查看最近请求、最近入库和当前并行区域。

- 已暂停：不会继续增加进度，使用原任务的「继续」恢复。
- 等待执行：后台队列尚未开始处理。
- 请求或入库时间持续更新：后台仍在工作。入库慢时查看已保存条数和阶段耗时。
- 120 秒无新活动：页面提示排查；心跳仍在线只能证明 Worker 还在运行，不证明业务进度正常。
- 队列没有对应执行项：数据库状态与实际队列不一致，下载诊断信息交管理员检查。
- 页面刷新失败：保留的是上次结果，应核对采集时间，不把旧画面当成实时状态。

旧版 Worker 正在执行的任务可查看原有高德请求记录和入库时间；详细响应耗时、保存条数和阶段心跳从新版 Worker 执行时开始记录，不补造旧日志。

管理员在服务器可按以下顺序检查；不要为了进度看似不动就重复创建全国任务：

```sh
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --since 15m --tail 100 worker
docker compose --env-file .env.production logs --since 15m --tail 100 api
docker stats --no-stream
```

后台日志出现 `discovery_log_unavailable` 或 `discovery_heartbeat_unavailable` 时，分别检查数据库迁移与 Redis 连接。监控写入失败不会把业务查询直接标成成功或强制重跑。
